# 国内电商数据：以统一 API 交付为主的选型

采购目标是一家主供应商提供跨平台统一 API。优先评估数说、魔镜、Nint 的企业交付；尚未确认任何一家同时满足淘京拼美全渠道、销量价格评价营销全类及自营后台数据。

本轮收紧了交付条件；原49组资料与信誉判断保留。重点深查18家，主评估仅3家。供应商有影响力、声称支持多平台、提供API，分别是三种证据，不能互相替代。

## 主评估名单

| 候选 | 为什么保留 | API证据 | 关键缺口 |
| --- | --- | --- | --- |

## 统一交付的验收要求

- **统一交付责任**：由一家主供应商负责上游采集、连接器、字段映射与维护；我们对接其 API 服务。允许有商品、销量、评价、营销多个端点，不要求所有功能挤在一个 URL。
- **统一数据模型**：要求同一商品/品牌跨渠道映射、金额与销量口径、时间粒度、缺失值定义。一个 Key 或一个入口尚不能证明这些已经统一。
- **完整覆盖矩阵**：逐一列淘宝/天猫、京东、拼多多、美团外卖/闪购/到店及抖音的销量、价格、评价原文、营销能力；把现成接口、项目定制、估算和不支持分开。
- **自营与竞品分开**：自营后台订单和广告账户仍需逐源授权；供应商封装连接与维护可减少开发对接。竞品监测不能当作对方真实订单或广告账单。
- **同一 API 下的验收样本**：要求多渠道同一品牌的实际 JSON、字段字典、增量与历史查询、分页/限额、更新时间和失败处理；本轮尚未取得这样的完整交付样本。

## 建议要求供应商交付的字段

以下是需求/验收字段建议，不是宣称任何供应商已经支持的接口定义。实际已核字段仍见原49组字段字典和下方文档。

| 数据类 | 建议字段 | 必须说明的口径 |
| --- | --- | --- |
| 共通字段 | platform, item_id / sku_id, shop_id, brand_id / category_id, observed_at, period_start / period_end, source_type / is_estimated | 跨平台身份、时间与观测/估算口径；供应商负责映射。 |
| 销量 | sales_units, sales_amount, sales_period, sales_basis, refund_basis | 区分累计/近30日/日销量、前台展示/估算/授权真实订单；不同口径不可直接相加。 |
| 商品与价格 | title, sku_attributes, list_price, sale_price, coupon / promotion, final_price_conditions, currency / unit, stock | 到手价需保留券、会员和凑单条件；分/元与币种统一。 |
| 用户评价 | review_id, content, rating, reviewed_at, sku, followup, images, shop_reply | 必须确认可交付评价原文；情绪分数、评价数不能代替原文。 |
| 营销：公开内容与促销 | campaign / promotion, creator_id, content_id, engagement, live_metrics, estimated_commerce_metrics | 包括促销、达人、内容、直播；估算指标需标注。 |
| 营销：自营广告后台 | ad_account_id, campaign_id, impressions, clicks, spend, attributed_orders, ROAS, attribution_window | 仅经授权账号；须确认广告平台与归因口径，不承诺竞品后台真实值。 |

## 本轮修正

- **Nint**：补证官网提供企业 API 服务；仍未获得公开标准端点/schema，不等于全产品统一 API 已验收。
- **九数云**：新增仪表板组件分页 JSON 文档（社区级协助），另有正式分析表导出；需建模、授权并确认生产支持。
- **飞瓜 / 欧特欧**：在 API 优先条件下退出主评估，保留原档案与专项用途。
- **聚水潭 / 餐道 / 蝉妈妈**：可补局部需求，不能单独满足统一跨淘京拼美、多大类的数据交付。

## 技术对照：统一入口并不自动统一字段

EveryInfra 当前公开能力目录使用 platform/action 选择功能，但业务字段仍不同：淘宝 id、京东 item_id、抖音 product_id；金额单位与销量周期也不同。其信誉仍待补证，且目录未列拼多多、美团，不能因技术入口整齐升为主供应商。目录原始响应和验证记录已保存；没有新增鉴权业务 API 成功记录。
