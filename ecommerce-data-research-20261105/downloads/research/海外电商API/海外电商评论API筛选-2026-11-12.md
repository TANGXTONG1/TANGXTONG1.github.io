# 海外电商评论 API：平台覆盖、价格与筛选结果

核验日期：2026-11-12。沿用此前需求：第三方统一 API、逐条评论正文优先，同时关注商品、价格、销量及营销数据。本轮核对 16 家供应商或产品线，另复核 EveryInfra / Qovia 的海外目录。不是市场穷尽清单。

**先试 Bright Data，再用 Apify 补覆盖；若核心市场是 Shopee / Lazada，再单独评估 Magpie。** 这三者仍没有一家被证明同时稳定覆盖九个目标平台的完整评论历史。若要求供应商完成跨站字段统一、固定交付和合同承诺，DataWeave 可进入企业询样，但公开资料不足以直接定为合格供应商。

**证据边界：本轮只核验公开官网、技术文档、机器目录和 Actor 元数据；没有注册海外账户、运行付费采集、取得自有业务样本或测量成功率。** 文件内的 schema 和文档示例不能算实测响应。此前 EveryInfra / Qovia 的国内小样本结果不适用于海外市场。

## 二、逐平台评论覆盖：不能用“支持平台”替代“支持评论正文”

下表的“独立”表示存在专门的评论输入/输出文档，**不表示已实调、全历史或所有国家覆盖**。“商品附带”表示商品结果含评论数组，深度待核。“社区”表示独立开发者维护，不等于 Apify 官方负责质量。

| 目标平台 | Bright Data | Apify 候选 | Magpie | 关键验收点 |
|---|---|---|---|---|
| Amazon | 独立评论采集器 | Apify 维护；文档约最多 500 条/商品 | 本轮仅核到商品/搜索，未核独立评论 | 登录墙、精选与全评论区别、最早日期、变体合并 |
| Walmart | 独立评论采集器 | Apify 维护 | 未核 | 翻页、转载/同步评论去重、商家回复 |
| eBay | 商品附带评论 | Apify 维护；含卖家交易反馈场景 | 未核 | 商品评分与卖家反馈必须分开 |
| Etsy | 商品附带评论 | 社区；listing 与 shop 输入 | 未核 | 商品评论与店铺全部评论分开 |
| AliExpress | 商品附带评论 | 社区；有原文/译文、追评字段 | 未核 | 原文和译文、SKU、追评、重复 |
| Temu | 当前公开目录未见现成对应项 | 找到新社区 Actor，但用户量过低，本轮不通过 | 未核 | 正文是否被删减；不能以星级/日期冒充评论正文 |
| Shopee | 当前公开目录未见现成对应项 | 社区；部分旧 Actor 维护中 | 独立 product-ratings / App ratings；App schema 列 8 地区 | 部分按店铺流匹配商品；Magpie 审核窗口和维护状态 |
| Lazada | 独立评论；目录代表域为马来西亚 | 社区；作者列东南亚六国 | 独立评论；文档列东南亚六国 | Bright 其余国家不能由马来西亚目录推断；正文、分页、回复 |

## 三、能拿到哪些字段，接入有多复杂

|---|---|---|

| Magpie Shopee App ratings | 官方示例含 cmtid、rating_star、comment、images；返回分页原始结构 | 固定 50 ratings/页；min_pages/max_pages 范围 1–100；Mon–Fri 08:00–17:00 Asia/Jakarta 工作时间审核；上限是参数允许值，非保证采满 |

Bright 统一用 `/datasets/v3/scrape` 或 `/trigger`，但需要不同 dataset_id 和字段映射；同步超过一分钟转异步，结果有 snapshot_id。技术上限包括 5,000 个活动任务/快照、异步输入 1GB、快照保存 30 天。**30 天是供应商暂存结果的生命周期，不是客户每天必须删除评论的规则。** 错误输入造成的失败仍可能计费。[调用文档](https://docs.brightdata.com/products/scrapers/amazon/introduction.md)、[技术限制](https://docs.brightdata.com/products/scrapers/limits.md)、[计费 FAQ](https://docs.brightdata.com/products/scrapers/scrapers-library/faqs.md)。

Bright 的 Amazon 文档简化示例与机器 schema 存在命名差异，例如示例用 `review_date` / `verified_purchase`，schema 用 `review_posted_date` / `is_verified`；应以试跑响应确认字段再固化映射。`max_reviews` 是请求上限，不是供应商保证能取到的评论数量。[端点示例](https://docs.brightdata.com/api-reference/scrapers/e-commerce-apis/amazon-reviews-collect-by-url)、[机器 schema](https://docs.brightdata.com/scrapers/gd_le8e811kzy4ggddlq.json)。

Oxylabs 当前新 Web API 使用 `webapi.oxylabs.io` 与 Bearer key；旧 Classic 教程使用 `realtime.oxylabs.io/v1/queries` 与用户名/密码。现行两套 Amazon 目录均未列独立 reviews 端点；商品/搜索端点覆盖许多电商站，不足以证明这些站都有可分页的评论原文接口。[评论教程](https://oxylabs.io/blog/how-to-scrape-amazon-reviews)、[Classic Amazon 目录](https://developers.oxylabs.io/products/web-scraper-api/targets/e-commerce/amazon)、[新 Web API 电商目录](https://developers.oxylabs.io/api-reference/dedicated-scrapers/commerce-scrapers.md)、[新接口认证](https://developers.oxylabs.io/api-reference)。

Apify 可统一以 `/v2/actors/{owner}~{actor}/runs` 启动，再读取 dataset；同步接口超过 300 秒可返回 408，大批量宜异步。Free / Starter / Scale / Business 的并发 run 数为 5 / 32 / 128 / 256，**并发 run 不是每秒请求数**。各 Actor 输入、结果 schema、重试、价格和维护者不同；仍需适配，但无需分别向每家电商实现采集。[同步接口](https://docs.apify.com/api/v2/actor-run-sync-get-dataset-items-post)、[维护归属](https://docs.apify.com/actors/running/store/actor-developers)。

Amazon Actor 本次最新有效计价列出评论事件与日期筛选事件，未列价格筛选或启动费；日期筛选 Free / Starter / Scale / Business 分别为 $0.0013 / $0.001 / $0.0008 / $0.0006 **每计费事件**，实际触发次数需看运行账单，不能直接解释为每次任务或每条交付评论。[官方公开计价元数据](https://api.apify.com/v2/acts/junglee~amazon-reviews-scraper)。Walmart Actor 则另有启动费；“from”单价不代表 Free 档价格。[Walmart 计价元数据](https://api.apify.com/v2/acts/e-commerce~walmart-reviews-scraper)。

Magpie 的 product-ratings 文档写明按页预扣、维护期新提交可返回 503 且不扣；App ratings 按成功页并在审核时收费。Lazada landing 与总费率说明对提交收费/成功收费存在表述差异，需向供应商确认。App ratings 的工作日人工审核是吞吐与时效限制，不能仅凭每页 50 条推算持续采集速度。[Shopee 文档](https://data.magpieiq.com/scraping-api/shopee)、[Lazada 文档](https://data.magpieiq.com/scraping-api/lazada)、[现行 OpenAPI](https://api.magpieiq.com/scraping/openapi.json)。

## 五、信誉与维护：不把客户 Logo 或 Star 当作成功率

- **Bright Data** 有实名 [Clootrack 案例](https://brightdata.com/customer-stories/clootrack)，场景涉及海量评论分析，案例使用的是代理基础设施；可证明供应商交付背景，不能证明本次四个评论采集器的覆盖率。
- **Oxylabs** 有实名 [Conductor 案例](https://oxylabs.io/resources/case-studies/conductor)，主要是搜索结果采集；证明公司能力，不代表商品评论完整性。
- **Apify** 可核公开 Actor 的维护者、更新时间、使用量和评分。本轮 Amazon Actor 公开元数据约 2,436 个近 30 日用户，评分 2.70/5（46 条），最近更新 2026-11-12。既有活跃使用，也有明显质量风险信号；不是直接推荐上生产。Temu 候选仅 2 用户/1 月活，不通过成熟度筛选。
- **Magpie** 官网列新加坡/印尼主体与品牌客户名单，但本轮未核到可独立佐证的具体评论 API 客户案例。其[公开 SLA](https://data.magpieiq.com/legal/sla)为 best effort，没有标准自动服务赔偿，工作时段支持；成熟度证据弱于前述大型供应商。[主体与客户名单](https://data.magpieiq.com/about)。
- **Traject** 有 [Publisher Rocket 案例](https://trajectdata.com/case-studies/how-publisher-rocket-built-scalable-author-friendly-insights-powered-by-direct-amazon-data/)；**DataWeave** 有 [SimpleTire 案例](https://dataweave.com/pages/case-study-pricing-intelligence-simple-tire)，后者主要为价格情报。**SellerApp** [客户案例](https://www.sellerapp.com/new/customer-stories.html)主要涉及广告与运营，不据此判定评论 API 已验收。

## 六、数据权利、免责和下架边界

本轮没有任何供应商通过“可任意转售、永久保存、再分发全部评论内容”的授权验收。采集技术可用、供应商的免责声明、客户案例和底层评论的内容使用权是不同问题。公开页缺少条款不记为“无限制”。

Magpie 的公开 SLA 为 best effort；其关于数据再分发和衍生产品的合作口径需要合同确认。Oxylabs 技术文档提醒客户审视目标网站条款/许可。Bright 和 Apify 的条款摘要见 [条款核验 JSON](terms-notes.json)，仍需按拟用站点、用途与实际合同确认。这里记录选型差异，不对具体业务作法律结论。

| 项目 | Bright Data | Apify |
|---|---|---|
| 数据与第三方权利 | 标准许可 §3.9 禁止用数据提供相似或竞争产品；§3.5/10.2 涉及第三方权利与授权责任 | 通用条款 §5.8 在法律允许范围内保留客户既有数据权利；§6.2 涉及使用责任，不是授予所有被采评论的版权 |
| 投诉 / 停用 | §2 允许在潜在责任、违法或违约等情形暂停服务 | 有侵权举报机制；Actor 条款 §9.5 允许删除或禁用严重违规的社区 Actor |
| 完整性 / 可用性 | §6 默认不保证持续无中断、无错误或数据完整准确；具体 SLA 另核 | 通用条款 §10 有类似免责；官方维护 Actor 有有限的描述符合保证和合理修正努力 |
| 社区作者责任 | 需要看具体服务合同 | Actor 条款 §8–9：社区作者默认没有持续维护、更新或支持义务；统一平台账户不消除这一差异 |

官方来源：[Bright Data 标准许可](https://brightdata.com/license)（核查页标 2026-10-12）、[Apify 通用条款](https://docs.apify.com/legal/general-terms-and-conditions)、[Apify Actor 条款](https://docs.apify.com/legal/actor-terms-and-conditions)（核查页标 2026-07-09）。

实际合同至少需要明确：评论正文/图片的使用范围，内部分析与向外再分发是否不同，保存/刷新要求，侵权投诉后的通知与删除流程，上游封禁或端点停用的处理，错误/空返回的扣费与退款，以及退出后的数据和密钥处理。**没有核到通用的“每日必须清除评论”规则；也不能将未核到解释为不受保存期限约束。**

## 七、下一轮如何比较真实成本与成功率

先用同一商品集验 Bright Data 与 Apify，Lazada 可加 Magpie；Shopee 单列。每站至少挑 20 个商品，覆盖不同评论量、店铺与国家，同一天取第一页、后续页和尽可能早的历史页。

统一记录：请求/任务成功率、非空正文率、唯一评论数、默认评价比例、重复率、最早/最新日期、回复与媒体字段、p50/p95 耗时、重试次数和实际扣费。**有效成本 = 所有相关扣费 ÷ 去重后的有效正文评论数 × 1,000**；另列订阅最低消费和闲置额度。HTTP 200、任务 COMPLETED、广告中的 99% uptime 都不是评论获取成功率。

对你们“尽量只接一家”的目标，建议要求供应商交付统一字段：platform / market / product_id / review_id / original_text / translated_text / rating / review_time / sku / verified_purchase / images / seller_reply / source_url / collected_at，并明确不可获得的字段。上述字段是采购需求，不代表任一平台全都现成支持。

## 八、现有 EveryInfra / Qovia 的海外补充核验

2026-11-12 新抓目录：EveryInfra 列 Amazon、Walmart、AliExpress 评论能力及 TikTok Shop 商品评论；eBay 要求 seller/item_id、Etsy 要求 shop，需区分卖家/店铺反馈。多数评论接口未列通用页码，不能由 limit 推断历史可翻页；TikTok Shop 有 page_token。所有这些均未进行本轮认证调用。

Qovia OpenAPI 中 Amazon reviews、Shopee reviews 标为 **coming_soon / beta**，不能列为已上线覆盖；TikTok 视频评论也不能代替 TikTok Shop 买家评价。此前 EveryInfra $1 试用额度于 11 月 7 日到期，本文不沿用其为当前可用余额。
