# 国内电商评论原文 API 复核

核验日期：2026 年 11 月 6 日。目标是由一家供应商通过 API 提供自有及竞品商品的逐条买家评价，并承担各商城的采集和维护。正文、评分、时间、规格、追评、图片和可取历史深度是重点。

**结论：尚无通过完整条件的主供应商。** Qovia、EveryInfra 仅是技术试验对象；两家的主体、客户案例与稳定交付证据仍不足，均未取得登录后的真实评论响应。拼多多、美团评论原文的可靠统一 API 仍是缺口。

## 撤下前轮主推荐

魔镜、Nint、数说不再作为当前评论 API 主推荐。前轮证据主要是市场与评价分析、企业数据服务或定制交付能力，未证明有现成的逐条商品评论端点与字段。魔镜旧 API 文档的维护情况待核，不能据此认定整个公司或业务停止维护。

## 字段验收重点

- 正文与关联：评论 ID、商品及 SKU ID、店铺、正文、评论时间、采集时间。
- 评分口径：淘天的好中差等级与京东的1到5星须保留原口径，不能直接当同一评分。
- 扩展内容：追评及时间、图片和视频地址、商家回复；没有列出的字段记为未核实。
- 深度与增量：每页数量、实际可读页数、最早时间、分页终止条件、重复率、新增与追评更新。
- 自营与竞品：按公开商品链接取数不代表能获得商家后台所有评价；每渠道的数据范围须实测。

## 这轮实际核验结果

1. Qovia 现行 OpenAPI 与京东评论文档可以读取；通过浏览器点击调试台，仍进入邮箱与验证码注册页面，未取得业务数据。
2. EveryInfra 公开能力目录返回 HTTP 200；淘天与京东评论有字段说明，未声明 page/cursor，目录中未列拼多多与美团。
3. TMAPI 官方淘宝评论页明确维护中，标注最后更新 2023-11-03；历史字段不能当现行服务。
4. Apify 上核到的美团/点评 Actor 明确尚未实现评论正文；另两款淘天/京东 Actor 评论限额分别为20条和10条，不能继承 Apify 平台的信誉成为成熟完整数据源。

## 文档示例与实际数据分开

Qovia 京东文档的一条评论示例摘录为“唯一的缺点就是颗粒太大了”，rating=5，sku_id=100006271091。同一文档分页示例是 total=20000、max_page=2。它说明总数和可翻页范围可以相差很大；这些数字不是通用上限，也不是本次成功取数。[示例来源](https://qovia.ai/zh/docs/api-reference/raw.jd.comments/)。

## 17 项详细判断

仅技术试验对象，非采购主荐

- 交付：https://api.qovia.ai；Bearer或x-api-key；统一request_id/data/meta信封。原始V2和标准化V1字段并不相同。
- 字段：淘天V1：text、rating_level、created_at、sku、images/videos、followup、shop_reply；V2是content等原样字段；京东：text、rating、sku_id、images、shop_reply，追评/视频未核。
- 深度：淘天参数page≤500、每页20，实际依has_more或maxPage/hasNextPage；京东参数page≤100、每页10，实际依max_page；均不保证到达参数上限或取得全量。
- 维护：2026-10-21日志宣布淘天/JD评价上线；当前标Live Beta，未独立验证成功率。
- 信誉：独立客户和完整主体仍待补证；明确文档只是技术验证基础，不满足采购验收。
