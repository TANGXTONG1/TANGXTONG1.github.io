第一轮开发顺序

  1. 先做共享基础层。两个供应商配置、商品 URL 校验、超时重试、任务状态、预算上限、凭据服务端保存、原始响应留存。价格/销量/营销数据另立能力项，不能由评论接口推断已支持。
  2. 国内先交付抖店 v1 与京东。同一轮补验业务优先级更高的淘天；成功前入口保持关闭。淘天共用实现，平台标记和商品身份仍分开。
  3. 海外先交付 Amazon、TikTok Shop、eBay、Walmart；Temu批量评论暂缓。补完后端 API 直接启动、轮询、分页导出。TikTok指定vistics，2页15条已验；使用product_id，避免空的productId。Walmart必须使用完整规范商品URL，并把0条任务判作业务失败。
  4. 保留缺口，不硬凑覆盖。Qovia淘天端点未验成；国内Apify已有首屏评论备选，见国内实测页；拼多多无Qovia公开端点；Temu只保留cliqtomedia详情与4条预览备选；eBay限商品目录评价。Bright Data 同样按实际商机触发评估。

建议上线门槛（尚未完成）

  1. 20 个代表任务，跨商品而非只重跑一个。每平台选 10 个已知有公开正文的商品、至少 3 个品类，连续 2 天。建议有效任务比例 ≥95%；空结果、目标源无评价、超时、阻断分别记录。
  2. 内容必须符合语义。人工抽查商品匹配、正文和星级；拒绝把 summary、error、纯评分、视频评论、交易反馈混作商品评论。去重后空文本、默认好评不进正文分析。
  3. 完整走一遍失败与增量。验证分页终止、预算耗尽、失败重试、重新运行去重、日期边界；不把“提交成功”或 SUCCEEDED 当成有效数据成功。
  4. 账单与结果逐项核对。记录真实用量事件、成功计费请求、有效正文数、运行时长和版本。达到目标后决定是否升级计划；不先承诺长期成功率或完整历史。
统一 API 任务模式与标准字段开发建议；不是供应商原生统一 schema

Apify 三步异步模式

POST https://api.apify.com/v2/actors/{owner}~{actor}/runs
Authorization: Bearer <APIFY_API_TOKEN>
Query: build=<验收版本>&maxTotalChargeUsd=<预算>&timeout=600
Body: 各平台输入 JSON

GET https://api.apify.com/v2/actor-runs/{runId}
→ 等待终态，并读取 defaultDatasetId

GET https://api.apify.com/v2/datasets/{defaultDatasetId}/items
    ?format=json&clean=true&offset=0&limit=1000
→ 分页导出、质量检查、落自己的库

终态 SUCCEEDED + 0 条有效正文 ≠ 数据验收成功

新版文档推荐 /v2/actors；旧 /v2/acts 是兼容路由。runId / Dataset ID 具有访问能力，不放公开报告。重试先确认是否已启动任务，避免盲目再次 POST 重复付费。

服务条款隐私与删除充值与退款

Apify

Community Actor 由第三方维护，平台不保证其输出质量或持续服务；可能被下架。Full permissions 可访问账户全部资源，Walmart 当前即要求该级别。正式部署应采用组织资源隔离，避免与无关历史数据混用。

Actor 条款区分程序使用许可与输出权利，并不代表来源网站授权。把采集能力集成进产品、对外展示或导出数据，仍需核清来源使用范围；若直接转售平台功能，使用政策要求事先书面批准。
